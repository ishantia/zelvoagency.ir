این فایل، راهنمای کامل و گام‌به‌گام است؛ حتی اگر تجربه کمی با Git و GitHub دارید، با دنبال کردن دقیق مراحل می‌توانید سایت را اجرا و منتشر کنید.

## پیش‌نیازها

برای اجرای این پروژه به دو ابزار نیاز دارید:

### ۱. Node.js

Node.js محیطی است که به آن اجازه اجرای پروژه‌های React را می‌دهد.

1. به آدرس [nodejs.org](https://nodejs.org) بروید.
2. نسخه **LTS** (نسخه پایدار بلندمدت) را دانلود و نصب کنید.
3. برای اطمینان از نصب صحیح، ترمینال (یا Command Prompt) را باز کنید و دستور زیر را وارد کنید:

```bash
node -v
npm -v
```

اگر شماره نسخه‌ای نمایش داده شد (مثلاً `v20.11.0`)، نصب با موفقیت انجام شده است.

### ۲. Git

Git ابزاری برای مدیریت نسخه‌های پروژه و آپلود آن در گیت‌هاب است.

1. به آدرس [git-scm.com](https://git-scm.com) بروید و آن را دانلود و نصب کنید.
2. برای اطمینان، دستور زیر را اجرا کنید:

```bash
git --version
```

### ۳. حساب کاربری گیت‌هاب

اگر حساب ندارید، در [github.com](https://github.com) یک حساب رایگان بسازید.

## نصب و اجرای پروژه روی سیستم شما

پس از دریافت فایل‌های پروژه (به‌صورت فولدر یا فایل zip)، مراحل زیر را دنبال کنید:

1. پوشه پروژه (`zelvo-agency`) را در مسیر دلخواه خود قرار دهید.
2. ترمینال را باز کرده و وارد پوشه پروژه شوید:

```bash
cd path/to/zelvo-agency
```

3. وابستگی‌های پروژه را نصب کنید (فقط یک‌بار لازم است، مگر اینکه `package.json` تغییر کند):

```bash
npm install
```

این دستور تمام کتابخانه‌های لازم (React، Vite، Tailwind و...) را دانلود و در پوشه `node_modules` قرار می‌دهد.

4. پروژه را در حالت توسعه اجرا کنید:

```bash
npm run dev
```

پس از اجرا، آدرسی شبیه `http://localhost:5173` در ترمینال نمایش داده می‌شود. آن را در مرورگر باز کنید تا سایت را ببینید. هر تغییری که در کد بدهید، بلافاصله در مرورگر به‌روزرسانی می‌شود.

## قرار دادن پروژه روی گیت (Git)

اگر پروژه هنوز به گیت متصل نشده، این دستورات را به ترتیب در ریشه پوشه پروژه اجرا کنید:

```bash
git init
```
> این دستور یک مخزن Git جدید و خالی در پوشه پروژه می‌سازد تا Git بتواند تغییرات را دنبال کند.

```bash
git add .
```
> تمام فایل‌های پروژه را برای ثبت در اولین نسخه (commit) آماده می‌کند.

```bash
git commit -m "Initial commit"
```
> یک نسخه (commit) از وضعیت فعلی پروژه با پیام «Initial commit» ثبت می‌کند. این پیام برای شناسایی تغییرات در آینده استفاده می‌شود.

```bash
git branch -M main
```
> نام شاخه (branch) اصلی پروژه را به `main` تغییر می‌دهد؛ نامی استاندارد که گیت‌هاب نیز از آن استفاده می‌کند.

## ساخت مخزن (Repository) در گیت‌هاب

1. وارد حساب گیت‌هاب خود شوید.
2. روی دکمه **New repository** (یا علامت `+` در بالای صفحه) کلیک کنید.
3. نامی برای مخزن انتخاب کنید؛ برای مثال `zelvo-agency`.
4. مخزن را **Public** انتخاب کنید (برای استفاده رایگان از GitHub Pages).
5. گزینه‌های «Add a README file» و مشابه را **فعال نکنید** (چون پروژه از قبل فایل‌های خودش را دارد).
6. روی **Create repository** کلیک کنید.

پس از ساخت، گیت‌هاب آدرسی شبیه زیر به شما نمایش می‌دهد:

```
https://github.com/USERNAME/zelvo-agency.git
```

## آپلود پروژه در گیت‌هاب

در ادامه دستورات بخش قبل، این دو دستور را وارد کنید (آدرس مخزن خودتان را جایگزین `YOUR_REPOSITORY_URL` کنید):

```bash
git remote add origin YOUR_REPOSITORY_URL
```
> آدرس مخزن گیت‌هاب را به‌عنوان مقصد پیش‌فرض («origin») برای این پروژه محلی ثبت می‌کند.

```bash
git push -u origin main
```
> تمام فایل‌های ثبت‌شده (commit شده) را به شاخه `main` در گیت‌هاب ارسال می‌کند. پرچم `-u` این شاخه را به‌عنوان مقصد پیش‌فرض برای دستورات `push` بعدی تنظیم می‌کند.

ممکن است در این مرحله گیت‌هاب از شما نام کاربری و یک **Personal Access Token** (به‌جای رمز عبور) بخواهد. این توکن را می‌توانید از مسیر
`GitHub → Settings → Developer settings → Personal access tokens` بسازید.

## فعال‌سازی GitHub Pages

این پروژه با یک فرآیند خودکار (GitHub Actions) در مسیر `.github/workflows/deploy.yml` همراه است که در هر بار `push` به شاخه `main`، به‌طور خودکار:

1. پروژه را با `npm ci` نصب می‌کند.
2. با `npm run build` نسخه نهایی را می‌سازد.
3. محتوای پوشه `dist` را روی GitHub Pages منتشر می‌کند.

برای فعال‌سازی این فرآیند:

1. در گیت‌هاب وارد مخزن پروژه شوید.
2. به تب **Settings** بروید.
3. از منوی سمت راست/چپ گزینه **Pages** را انتخاب کنید.
4. در بخش **Build and deployment**، مقدار **Source** را روی **GitHub Actions** قرار دهید (نه «Deploy from a branch»).
5. به تب **Actions** بروید؛ باید فرآیند «Deploy Zelvo Agency to GitHub Pages» را در حال اجرا یا تکمیل‌شده ببینید.
6. پس از اتمام موفق، آدرس سایت شما (مثلاً `https://USERNAME.github.io/zelvo-agency/`) در همان بخش Pages نمایش داده می‌شود.

> **نکته مهم درباره base path:**
> اگر می‌خواهید سایت را **بدون دامنه اختصاصی** و از مسیر یک مخزن پروژه (نه `username.github.io`) منتشر کنید، باید در فایل `vite.config.js` مقدار `base` را به نام مخزن خودتان تغییر دهید:
> ```js
> base: '/zelvo-agency/',
> ```
> اگر از دامنه اختصاصی (`zelvoagency.ir`) استفاده می‌کنید، مقدار `base: '/'` را همان‌طور که هست نگه دارید.

## اتصال دامنه اختصاصی zelvoagency.ir

پروژه از قبل شامل فایل `public/CNAME` با محتوای `zelvoagency.ir` است که پس از هر `build`، در پوشه `dist` نیز کپی می‌شود؛ این فایل به GitHub Pages می‌گوید این سایت باید روی چه دامنه‌ای پاسخ دهد.

### مرحله ۱: تنظیمات در گیت‌هاب

1. در تب **Settings → Pages** مخزن، در بخش **Custom domain**، مقدار `zelvoagency.ir` را وارد کرده و **Save** را بزنید.
2. گیت‌هاب به‌صورت خودکار فایل CNAME را بررسی می‌کند (چون از قبل در پروژه وجود دارد).

### مرحله ۲: تنظیمات DNS نزد ثبت‌کننده دامنه

به پنل مدیریت دامنه‌ای که `zelvoagency.ir` را از آن خریداری کرده‌اید بروید و رکوردهای زیر را اضافه کنید:

**برای دامنه اصلی (zelvoagency.ir) — چهار رکورد A به آی‌پی‌های گیت‌هاب:**

| نوع | نام (Host) | مقدار (Value) |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |

**برای زیردامنه www (اختیاری اما پیشنهادی):**

| نوع | نام (Host) | مقدار (Value) |
|---|---|---|
| CNAME | www | USERNAME.github.io |

> به‌جای `USERNAME` نام کاربری گیت‌هاب خودتان را وارد کنید.

### مرحله ۳: صبر برای انتشار DNS

تغییرات DNS معمولاً بین چند دقیقه تا چند ساعت (و گاهی تا ۴۸ ساعت) طول می‌کشد تا در سراسر دنیا منتشر شود.

### مرحله ۴: فعال‌سازی HTTPS

پس از اینکه DNS به‌درستی تنظیم شد:

1. دوباره به **Settings → Pages** در گیت‌هاب بروید.
2. گزینه **Enforce HTTPS** را فعال کنید.
3. اگر این گزینه در دسترس نبود، چند دقیقه تا چند ساعت صبر کنید؛ گیت‌هاب باید ابتدا گواهی SSL را برای دامنه شما صادر کند.

## رفع مشکلات رایج

### صفحه سفید خالی (Blank Page) پس از انتشار
معمولاً به‌دلیل نادرست بودن مقدار `base` در `vite.config.js` است. اگر از دامنه اختصاصی استفاده می‌کنید، `base` باید `'/'` باشد. اگر از مسیر مخزن استفاده می‌کنید، باید `'/نام-مخزن/'` باشد.

### خطای 404 پس از دیپلوی
- بررسی کنید Source در تنظیمات Pages روی **GitHub Actions** تنظیم شده باشد.
- بررسی کنید فرآیند Actions با موفقیت کامل شده باشد (تب Actions در گیت‌هاب).

### فایل‌های CSS یا تصاویر بارگذاری نمی‌شوند
معمولاً به همان دلیل نادرست بودن `base` است؛ مسیرهای فایل‌ها نسبت به مقدار `base` ساخته می‌شوند.

### دامنه اختصاصی کار نمی‌کند
- مطمئن شوید فایل `public/CNAME` دقیقاً حاوی `zelvoagency.ir` (بدون فاصله یا خط اضافه) است.
- مطمئن شوید رکوردهای A و CNAME دقیقاً مطابق جدول بالا ثبت شده‌اند.
- به یاد داشته باشید انتشار DNS ممکن است زمان‌بر باشد.

### HTTPS فوراً فعال نمی‌شود
صدور گواهی SSL توسط گیت‌هاب گاهی چند ساعت طول می‌کشد؛ این طبیعی است و نیازی به اقدام اضافی نیست.

### شکست فرآیند GitHub Actions
به تب **Actions** در گیت‌هاب بروید و روی فرآیند ناموفق کلیک کنید تا جزئیات خطا را ببینید. رایج‌ترین دلیل، وجود خطای نحوی در کد یا عدم تطابق نسخه Node.js است (این پروژه با Node.js نسخه ۲۰ تنظیم شده است).

## راهنمای کامل انتشار سایت Zelvo Agency روی GitHub Pages

این بخش، خلاصه‌ای صفر تا صد از کل مسیر انتشار است:

1. **نصب Node.js** از [nodejs.org](https://nodejs.org) (نسخه LTS).
2. **نصب Git** از [git-scm.com](https://git-scm.com).
3. **ساخت حساب گیت‌هاب** در [github.com](https://github.com) (در صورت نداشتن حساب).
4. **اجرای محلی پروژه:**
   ```bash
   npm install
   npm run dev
   ```
5. **ثبت پروژه در Git:**
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   ```
6. **ساخت مخزن جدید** در گیت‌هاب (Public، بدون README).
7. **اتصال و ارسال پروژه:**
   ```bash
   git remote add origin YOUR_REPOSITORY_URL
   git push -u origin main
   ```
8. **فعال‌سازی GitHub Pages:** `Settings → Pages → Source → GitHub Actions`.
9. **افزودن دامنه اختصاصی:** وارد کردن `zelvoagency.ir` در بخش Custom domain.
10. **تنظیم DNS:** افزودن رکوردهای A (برای دامنه اصلی) و CNAME (برای www) نزد ثبت‌کننده دامنه.
11. **فعال‌سازی HTTPS:** فعال کردن گزینه Enforce HTTPS پس از انتشار DNS.
12. **به‌روزرسانی‌های بعدی:** فقط با `git add . && git commit -m "..." && git push`.

با تکمیل این مراحل، سایت Zelvo Agency روی آدرس `https://zelvoagency.ir` در دسترس عموم قرار می‌گیرد.
